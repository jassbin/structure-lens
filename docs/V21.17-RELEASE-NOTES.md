# V21.17 / 1.0.54 Release Notes (照一照流程改版心得)

> 微信小程序版「照妖镜 / 解忧果」 v21.17 后端 + 1.0.54 前端改版的设计思路、踩坑与结论。
> 本文只讲思路与经验，不含任何密钥 / AppID。

## 一、本版本改了什么

- 后端 server/ : 1.0.0-v21.17，核心是 POST /api/precheck 三结局流程。
- 前端 wechat-miniprogram/ : 1.0.54，照一照交互重做。
- 三页链路（结构解析 → 行动缝隙 → 未来推演）与追问 / 分享 / 信源打开能力保留。

## 二、照一照"三结局"设计（最重要）

一次点击 = 搜索 + 三结局分支：
- diggable : 搜索命中且事件清晰 → 直接分析，不给多余提问。
- align : 搜索结果拿不准（同名事件 / 信息不足）→ 一句话让用户确认；确认就继续，补充就带补充重走一次。
- need_detail : 搜索零命中（多为私人 / 小众事件）→ AI 能看懂就直接分析；真看不懂才让用户补一句源头信息。

安全阀：round >= 3 强制放行，防止无限补充形成死循环。

### 设计原则
- 用户省力是核心：大众都知道的事件，输入一个关键词就够，剩下全自动。
- 不区分"网上事件"和"私人事件"：AI 无法可靠区分，且私人话题在网上往往有大量同款讨论。
  曾做"公私分流"设计，实测让用户多走无谓流程，已废弃。
- 搜索结果本身就是"懂不懂"最好的信号：搜到即可按公开素材分析；搜不到但描述清楚就按用户资料分析；
  又搜不到又模糊才追问。命中一条相关讨论就算"懂"，不要把"搜到权威定义"当门槛。

## 三、追问与操作体验的取舍

- 追问提交后不整页重载，保留当前页面内容，角落轻量加载，用户可边看边等。
- 追问重算通过 fresh / regenerate 强制绕过缓存，保证新结论。
- 三页底部统一两个按钮：进入下一步（金色主按钮）+ 分享；返回 / 重算收敛，减少噪音。

## 四、平台 / 部署踩坑

### 1. 版本 041→047 连环失败
- 现象：wxcloud run:deploy 卡构建、最终 500，前端 1.0.4x 同步失败。
- 根因：DescribeCloudBaseRunBuildLog / ProcessLog 显示 300502 build not found，平台构建服务短暂异常，
  并非代码问题。
- 教训：构建恢复后仅需 1-2 分钟，别把异常当常态反复重试；部署前本地 node index.js 冒烟，
  部署后 curl /healthz 看 version 与 lastUsedModel 即可；前端需在公众平台设体验版才对用户生效。

### 2. 密钥与配置
- 后端密钥走云端环境变量注入，代码只引用占位名：AI_PROVIDER_BASE_URL / API_KEY / MODEL，
  以及失败兜底 AI_FALLBACK_* 系列。具体见 .env.example。
- 本地密钥只存在本机指定位置，不入仓库；仓库只放 .env.example 占位，真实值由云端环境变量注入。
- 小程序 AppID 属敏感配置，仓库内一律清空为 ""，开发者在本机填入。

## 五、本地验证要点

- 后端：server/ 下 npm install，用 .env.example 起本地变量；线上 curl /healthz 看版本。
- 前端：微信开发者工具导入 wechat-miniprogram/ 填本机 AppID 即可预览。
- 安全自查：rg -i "api[_-]?key | deepseek[_-]?token | private_key | BEGIN" 不应命中真实值；appid 仅允许空串。
