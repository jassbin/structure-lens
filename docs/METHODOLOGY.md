# 结构透镜 · 设计理念与方法论

> 照妖镜，专治"表面一套、底下一套"。
>
> 本文沉淀「结构透镜（Structure Lens）」的产品哲学、两套核心方法论
> （**结构透镜 8 步深度穿透** + **清醒行动主义 6 步行动引擎**），以及它们如何被产品化。

---

## 一、我们相信什么（设计理念）

1. **表象是给人看的，结构才是真在运作的。**
   任何事件、关系、组织、舆论，表面叙事往往是被设计出来的；真正决定走向的是底层结构（谁想要什么、什么在约束谁、什么在自我强化）。产品的第一使命，是帮人从"表面一套"看到"底下一套"。

2. **看清，不等于看穿情绪；看穿，不等于陷入无力。**
   很多"清醒"的人，看清之后反而更内耗——因为看清了结构却找不到抓手。所以我们不止步于分析，必须补上"看清之后怎么办"。

3. **冷静、诚实、克制，但一定给抓手。**
   不鸡汤、不美化痛苦、不灌情绪安慰；但也不冷冰冰甩结论。每一次输出都要落到"用户下一步能做什么"。

4. **可证伪优先于自洽。**
   分析要敢给可证伪条件、敢被质疑、敢被推翻（"我不同意"可从任意一步重算）。结构假设需要被多个事件验证后才"点亮"。

5. **数据属于用户，策略一致。**
   免登录也能完整体验，数据存本地；登录后上云。分析、结构地图、行动方案三类数据遵循同一套"本地 + 云端"策略。

---

## 二、结构透镜 · 8 步深度穿透

输入一个事件/困惑，先经过**可挖掘性分诊**（太浅→反问补充；不适用→引导；够具体→放行），
再**静默联网核对事实**（搜到才用、搜不到照常分析，不打扰用户），然后逐层穿透：

| 步 | 名称 | 做什么 |
|----|------|--------|
| 1 | 表象采集 | 还原事件"官方叙事 / 表面说法" |
| 2 | 主体与动机 | 涉及哪些主体、各自真正想要什么 |
| 3 | 约束与筹码 | 谁被什么约束、手里有什么筹码 |
| 4 | 结构还原 | 原本以为 vs 真实运作 vs 为什么这样 |
| 5 | 反转识别 | 找出与直觉相悖的关键反转点 |
| 6 | 魔鬼代言人 | 对每条判断给出**反驳 + 必答回应**（元认知审计） |
| 7 | 可证伪条件 | 给出"什么情况下本结论会被推翻" |
| 8 | 金句结论 | 一句穿透性结论 + 底层结构骨架 |

产出 = **金句结论 + 结构骨架（perceivedAs / actualStructure / whySo / root）+ 反转 + 可证伪条件 + 来源**。

### 结构地图（复利资产）
每次分析的结构骨架会并入用户的「结构地图」。同名结构累计命中，达阈值即从"假设"点亮为"已验证"——
让用户看到"同一套底层结构在不同事件里反复出现"，把一次性洞察变成可复用的认知资产。

## 三、清醒行动主义（Clear-Actionism）· 6 步行动引擎

> 定位：结构透镜让人「看清结构」；清醒行动主义负责「看清之后不瘫痪、去行动」。

入口是报告页底部醒目的 **「看清了，然后呢？」** 卡片，点击进入独立全屏行动页（不污染常驻导航）。

### 世界观（严格遵守，不许滑向鸡汤）
- 痛是信号，不是命运；不美化痛苦、不赋予超验意义。
- 行动优先于反思；盲目行动也好过原地内耗（至少能拿到反馈）。
- 可改变则改；不可改变则用"清醒安慰剂"调节——**使用它，但绝不误当真理**。
- 区分"能动而不动"（点破、批判）与"真的无法行动"（共情、给调节）。

### 6 步
| 步 | 名称 | 做什么 |
|----|------|--------|
| 1 | 痛点定位 | 把情绪痛还原成冷静"信号"（生物信号/结构信号），说清真正在痛什么 |
| 2 | 可控性分诊 | 把要素分进三筐：**可改变的环境 / 可改变的行为 / 不可控** |
| 3 | 自欺检测 | 判断"能动而不动 / 真的无法行动 / 无法判定"，给自检问句 |
| 4 | 最小行动 | 针对"可改变"，给 1–3 个**今天就能做**的最小动作 |
| 5 | 缝隙扫描 | 针对结构，找 1–2 个现实缝隙（类型 + 具体做法） |
| 6 | 清醒安慰剂 | 针对"不可改变"，给不自欺的调节法 + 一句收尾原则 |

产出 = 一份结构化「行动方案」，每步与来源分析的 input / verdict / skeleton 强关联。

### 动态事件视角（不套模板）
同一件事，站在不同人的立场，"能动/该动"的答案完全不同。所以候选视角**不写死**，而由 AI 依据本次事件动态抽取
2–4 个真正相关的核心角色（如孙宇晨天价香蕉事件 → 币圈投资者 / 围观网友 / 艺术市场从业者，绝不套用父母/子女），
并判定"用户最可能是谁"作为默认视角。行动页顶部提供视角切换器，换一个视角即**围绕该身份重新生成整套方案**——
让建议永远服务于"此刻的你到底是谁"，而不是一份放之四海的通用清单。

### 单步追问 · 必须先正面回答，再联动重算
每个行动步下方都有「我不同意 / 追问这一节」的人机辩论组件。这里的铁律是：**先给实质，再谈立场**。
- 模型必须先在 `answer` 字段写出针对用户观点的**实质回答**（追问型→往深一层给机制与更具体做法；反驳型→给完整推理链），
  严禁"你说得有道理但…""已考虑你的意见"这类只表态、不解释的空话；`answer` 恒有值，是给用户看的主内容。
- 再给结构化裁定 `stance`（采纳 absorb / 折中 compromise / 维持 hold）与简短归档 `reason`。
- 采纳或折中后，**强制增量重算所有受影响的下游步骤并联动更新**，杜绝"改了这步、后面还自相矛盾"。
- 每一轮辩论都留痕（`debates` 字典按步归档），可回看这份方案是如何被你一步步质疑、打磨出来的。

### 解忧果（行动方案的浏览入口）
底部第三个 Tab **「解忧果」🌱**，聚合用户攒下的每一份行动方案，可回看、可再进入。
它把"看清→行动"从一次性动作，变成可积累、可回访的成长轨迹。

## 四、如何产品化（落地策略）

### 1. 三层数据、一套策略
| 数据 | 免登录 | 登录 |
|------|--------|------|
| 分析报告 | localStorage | 云端 `analyses` 表 |
| 结构地图 | 本地折叠重建 | 云端 `structure_nodes` + 双向同步 |
| 行动方案 | localStorage | 云端 `analyses.action_plan` 列 |

行动方案不新建表，而作为分析行的一个 JSON 列——天然随分析一起云端持久化与回流，改动小、语义一致。
再次进入行动页：**先读本地 → 再读云端 → 都没有才生成**，命中云端会回灌本地，实现秒开。

### 2. 感知优先的等待体验
深度分析（8 步）与行动方案生成都需 10~20 秒——这是内容深度的代价，压不下去。
因此不硬砍质量，而是**给明确预期**：全屏过渡遮罩（旋转环 + 分阶段文案 + 乐观进度条 + 计时），
让等待可读、不误判为卡死。分析页与行动页遮罩**共用同一套版式规范**，仅主色区分（分析=品牌蓝，行动=薄荷绿）。

### 3. 可质疑、可推翻
分析侧："魔鬼代言人"对每条判断强制"反驳 + 回应"；"我不同意"可从任意步重算下游；结构需多事件验证才点亮。
行动侧：每步可「追问/反驳」，模型**先给实质回答再谈立场**，采纳后**联动重算下游**，全程留痕。
产品姿态是**诚实的工具**，而非权威的裁判。

### 4. 增长闭环
看清（分析）→ 沉淀（结构地图）→ 行动（清醒行动主义）→ 回访（解忧果）→ 分享（只读快照卡）。
每一环都产生可分享、可积累的资产，形成自然的传播与留存。

## 五、语气与文案基调（贯穿全局）
- 冷静、诚实、克制；不鸡汤、不恐吓、不装神。
- 每次输出都要落到"下一步能做什么"。
- 关键概念旁提供 `?` 注释气泡（InfoTip），降低理解门槛。
- 全部 UI 文案走 i18n（zh-CN / en-US），不硬编码。
